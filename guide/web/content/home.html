Overview

A Markov reward process (MRP) is a list of states, the probability of moving from each state to each other state in one step, and a reward earned in each state. From those three things you get the expected value of a cow, how a herd is spread over states as time passes, and what replacing a cow is worth. In CowMRP the cow is described by three variables only, (lactation, days in milk, days pregnant), and every probability and reward is a separate, documented module you can read and change.

It is written for researchers, graduate students and advisers who want to ask keep-or-replace and herd-projection questions of a model they can inspect, and for developers who want to build another animal domain on the same engine.

What you can do

Compare two cowsProject an open and a pregnant cow forward and compare their expected value over time. Keep or cullThe break-even sale value of every cow: keep, replace, and their difference, kept apart. Project a herdLoad your own records, carry the herd forward, and write tables and dashboards. YoungstockThe calf, heifer and first-calving chain, as a second domain on the same engine. Three time resolutionsMonth, week or day steps; one setting carries through states, probabilities, rewards and outputs. Expected, stochastic or Monte CarloThe exact distribution by default; sampled paths and Monte Carlo when you ask for them.

Install

pip install cowmrp                 # engine + domains (numpy, pandas, scipy)
pip install "cowmrp[plot]"         # + matplotlib, plotly: dashboards and figures

Then follow Getting started: a whole farm in a dozen lines, with the output it prints.

Design principles

  • The scientific model is the reference. The package changes how the model is reached, not what it computes; results are tested against saved outputs of the original scripts.
  • One engine, many domains. cowmrp.mrp knows no animal. Cow and youngstock sit on top of it, and a check enforces that the engine imports no domain.
  • Nothing is hidden. Every probability and reward is its own small module; the replacement cost is charged in an explicit comparison, not folded into the reward vector.
  • Fast by default. The exact expected distribution is the default mode; sampled modes are available but never run unless you select them.
