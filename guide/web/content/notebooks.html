Examples and downloads

Download. Download the repository as a ZIP (it contains user_examples/), browse the examples folder on GitHub, or see below for git clone. The notebooks are examples, not limits: CowMRP supports monthly, weekly and daily resolution and your own domains, and you can write your own notebooks and workflows with it.

Five Jupyter notebooks show how to use CowMRP after pip install. They import only from the installed package, and each one starts with an install cell. Open one, run the cells from top to bottom, then replace the example CSV file with your own data. The notebooks, their data files and the custom-domain folder live together in the user_examples/ folder of the GitHub repository; they are not part of the Python package.

1. Get the examples

Either of these gives you the folder; use the one you prefer.

# the whole repository
git clone {{REPO_URL}}.git
cd cow-mrp/user_examples

# or only the examples folder
git clone --depth 1 --filter=blob:none --sparse {{REPO_URL}}.git
cd cow-mrp
git sparse-checkout set user_examples
cd user_examples

Without Git: open the repository on GitHub, choose Code and Download ZIP, unpack it and open the user_examples folder. Keep the whole folder together: the notebooks read data/... next to themselves, and notebook 5 reads custom_domain/.

2. Install and open

pip install "cowmrp[plot,excel]"
pip install notebook
jupyter notebook

The plot extra installs Plotly and Matplotlib (figures and the interactive dashboards); the excel extra installs openpyxl (the keep/cull Excel workbook that notebook 1 points to). The notebooks themselves use Plotly. The base package alone is enough for the calculations. Use a new virtual environment if you can.

4. Use your own farm

Cows (notebooks 1 to 3). A CSV with one row per cow and the columns lactation (1 to 10), dim_days (days in milk), dp_days (days pregnant, 0 if open) and optionally cow_id. Set HERD_CSV to your file. The loader maps each cow to a model state from these three numbers; a cow it cannot map is listed, never dropped silently. If you do not set a file, the example herd is used.

Young stock (notebook 4). A CSV with stage (CALF, HEIFER, BREEDING or PREGNANT), age_months and dp_months.

Defaults and settings. Everything you do not set uses its default. In notebook 1 you list only the economic settings you want to change in MY_SETTINGS; the notebook prints every setting that can be changed (see also the Defaults page).

Domain and time resolution. The cow notebooks use the "cow" domain (build_model("cow")) and the youngstock notebook uses "youngstock". Month is the default time resolution. To use week or day, set COW_TIME_UNIT to week or day before the first import of cowmrp, as the notebooks show; one resolution per Python session, and day resolution is very large (see Getting started).

Limits. The model sees only lactation, days in milk and days pregnant of each cow. dp_days can be left out of the file (then every cow is treated as open), and the table shows the day value of the model state a cow was mapped to. The example CSV is month-binned synthetic data: at week or day resolution some of its cows have no state, and the loader stops and lists them. Keep/cull does not credit the salvage value of a sale; your offer is that credit. The youngstock domain has no rewards, no values and no keep/cull, and notebook 4 needs month resolution. Values in notebook 2 are expected cows, not a forecast of individual animals.

Daily resolution. The CowMRP package supports monthly, weekly and daily resolution. The five notebooks are illustrative examples, not limits of the package: you can build your own daily-resolution workflows, with cow data that is compatible with the daily state rules. The bundled 1,000-cow CSV is intended for monthly resolution and does not map completely at daily resolution (28 cows have no state). The complete example notebooks have not been verified at daily resolution, and daily runtime and memory requirements (about 2 million cow states) have not been benchmarked. The youngstock notebook is limited to monthly resolution because its CSV has ages in months.

Synthetic data. data/cows_1000.csv (1,000 cows sampled from a herd that an earlier version of CowMRP generated from its own model) and data/youngstock_500.csv (random, fixed seed) are synthetic. They contain no real animals and are there to show the file format.

5. Your own domain on the generic engine

The MRP engine (cowmrp.mrp) contains no cow knowledge. It needs a domain: a Python package, a folder whose name is the domain name, with parameters.py (TIME_UNIT, UNIT_DAYS), states.py (build_<name>_states(), a table with a state_id column), probabilities.py (compute_probabilities), transitions.py (compute_transitions, the non-zero entries of the matrix) and, if you want values, rewards.py (compute_rewards, including a total). Optional hooks go in notebook_hooks.py. Put the folder on sys.path and call build_model("<name>"): the engine builds the states, the probabilities, the transition matrix (and checks that every row sums to 1) and the reward vector, and evaluate solves the state values. validate_domain lists missing pieces first.

Notebook 5 does this with a toy insemination model in user_examples/custom_domain/insemination/, whose README.md lists the interface rules. Its numbers are illustrative, not biological or economic estimates. Copy the folder, rename it and edit the files to model your own process.

Where the files are

The installed package (pip install cowmrp) contains the engine, the domains, the plotting helpers and a small tutorial herd. The user_examples/ notebooks, scripts, CSV files and the custom-domain folder are obtained separately from the GitHub repository, as described above; they are not in the wheel or in the source distribution. The same folder holds check_installed.py, which builds the wheel, installs it into a clean virtual environment and runs every notebook there, so that the notebooks are tested against the installed package.
