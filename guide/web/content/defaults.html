Defaults

Defaults and how they work

Every value in CowMRP has a default, and the defaults are the model. This page says which values you can change, how, and what stays fixed.

What a default is

The package runs with no configuration: the biological rates, the prices and costs, the time step (month), the discount rate and the simulation mode all have defaults. The results at the defaults are the reference results of the model, and the test suite compares them with saved reference numbers. A default is never replaced silently: you change a value explicitly, for one run, and when the run is over the default is back.

The biological and management parameters (conception, culling and mortality rates, the milk curve, the waiting period and so on) are not overridable through the API. They are the scientific content of the model; they are documented with their sources on the Provenance page and changed only in the source, after review.

Overriding an economic setting

An override lasts for one with block. Only the settings you name change; every other setting keeps exactly its default, and every value is restored when the block ends, also after an error.

from cowmrp.model import build_model
from cowmrp.domains.cow.economics import economic_overrides, reprice_model
from cowmrp.domains.cow.keepcull import keep_cull_table

model = build_model("cow")
with economic_overrides(MILK_PRICE_PER_KG=0.52, REARING_COST=2800):
    scenario = reprice_model(model)                  # rewards recomputed; states and the transition matrix are the same objects
    table = keep_cull_table(herd, scenario)          # keep/cull inside the block, so REARING_COST applies
# here every value is back to its default

From the command line: python runners/cow/farm/keepcull.py --offer 900 --set REARING_COST=2800 --set MILK_PRICE_PER_KG=0.52. The results go to a separate keepcull_scenario/ folder together with a file that records every overridden value, so a scenario is never mistaken for the default run. The keep/cull example runs the same table at the default and at a different rearing cost.

What the override guarantees, and what it does not

  • Probabilities cannot change. reprice_model recomputes the rewards only; the transition matrix and the biological probabilities are the same objects as in the model you pass in.
  • Rearing cost is read by the keep/cull layer, not by the reward vector (the replacement cost is charged in the cow-versus-heifer comparison). Call the keep/cull function inside the block.
  • A warning is given for combinations that are easy to get wrong, for example overriding the beef price without the dressing percentage, or switching on the days-open penalty (off by default because it overlaps flows the model already books).
  • Not thread-safe. The override replaces module-level values of the running process: use it in sequential scripts and notebooks, one scenario at a time. Nested override blocks are refused.
  • Scenario results are not the defaults. A table made inside a block says nothing about the reference model; the saved baselines apply to the defaults only.
  • The discount rate and the sale offer are not overridden this way: they are arguments of the functions (see above).

Reading the defaults

The table is read from the package when this page is built, so it always shows the values the code uses. A value shown as "not recorded" is a value whose price year, region or source the repository does not record; nothing is filled in by guess. The prices are US market figures: replace them with your own before using the money results on a farm.
