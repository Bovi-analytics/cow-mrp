# guide/ - CowMRP documentation site

A documentation site built from the code (the tutorial, a file guide and the API reference from the docstrings). Nothing in `src/` or
`runners/` is modified by it. The newer website is in `guide/web/` (see its README).

## Build it

```
pip install -r guide/requirements-docs.txt   # pdoc plus the packages cowmrp imports
python guide/build.py            # writes guide/site/ ; open guide/site/index.html
python guide/build.py --check    # only list the functions that have no docstring
```

## What is here

| Path | What it is | Edited by |
|---|---|---|
| `build.py` | Builds the whole site in one command | by hand |
| `tutorial.html` | Walkthrough: install, farm data and the tutorial herd, cow A vs B, keep/cull, whole-farm projection, expected vs stochastic vs Monte Carlo, time resolution, environmental outputs, own domain, tests | by hand |
| `assets/` | Figures the tutorial shows; refreshed from `runners/cow/outputs/` on every local build | by `build.py` |
| `check_removed_domain.py` | Searches `guide/` and `guide/site/` for the name of the domain this guide leaves out; prints every hit or "0 hits" | by hand |
| `check_links.py` | Broken-link check on `site/` (`python guide/check_links.py`) | by hand |
| `requirements-docs.txt` | `pdoc` and the few packages `mrp`/`domains` import; enough to build on a fresh clone | by hand |
| `site/` | The generated site: `index.html`, `tutorial.html`, `files.html`, `api/` | never (generated, git-ignored) |

## How it stays up to date

- **API reference** (`site/api/`) is generated by [pdoc](https://pdoc.dev) from the docstrings of the `cowmrp` package in `src/` (engine, model API, io, viz, cow and youngstock domains).
- **File guide** (`site/files.html`) takes the first sentence of each module's docstring. A file without one shows "no description".
- Both change automatically when the code changes: rerun `python guide/build.py`, or push to `main` and
  `.github/workflows/guide.yml` rebuilds and publishes it (only when `src/`, `guide/`, `examples/`, `README.md` or `pyproject.toml` changed; a pull request builds and checks links but does not deploy).
- Only `tutorial.html` is hand-written. If a command or output it shows changes, update it.
- The site is only as good as the docstrings: a new function without one appears as a bare signature.
  `python guide/build.py --check` lists them.

## Publishing (GitHub Pages)

Once, in the GitHub repository: **Settings -> Pages -> Source: GitHub Actions** (needs admin rights on the repo, e.g. the
supervisor). After that every push to `main` publishes the site at `https://<owner>.github.io/<repo>/`.

## Reading order for a newcomer

1. `site/tutorial.html` - what the model is and how to run it.
2. `site/files.html` - which file does what.
3. `site/api/index.html` - function-level reference.
4. `README.md`, then the docstrings of `src/cowmrp/domains/cow/parameters.py` and `state_constraints.py` before changing any probability, reward or state.
